Same person or not?

A bank screens every customer against sanctions, politically exposed person and adverse-media lists, and most matches are just namesakes. Vera clears the obvious ones, keeps every real or uncertain match for a person, and shows the records behind each decision.

curl -fsSL https://samuelgrosz.github.io/vera-hackathon-submission/install.sh | sh

Downloads Vera to ~/vera-cli and adds it to your PATH. Open a new terminal, then run vera /path/to/screening/dev.

irm https://samuelgrosz.github.io/vera-hackathon-submission/install.ps1 | iex

Run in PowerShell. Downloads Vera to %USERPROFILE%\vera-cli and adds it to your PATH. Then run vera C:\path\to\screening\dev.

Using Vera

Vera is the command-line app on top of the screening system. Pass the data folder when you start Vera:

./vera /path/to/screening/dev  # macOS or Linux, from the repo folder
vera C:\path\to\screening\dev  # Windows cmd or PowerShell
Run Vera
Decides every hit and shows the summary, including the practice-label score and any unsafe clearances.
Review queue
Open alerts, then an alert's hits, then a hit side by side with the customer. On a hit, t shows the decision tree, e drafts emails and d records your own decision.
Decision guide
An interactive yes/no walk through the identity rules.
Draft all emails
For every REVIEW hit: an internal draft and, where the customer can help, a neutral customer draft. Drafts are checked for tipping-off words and are never sent.

Keys: ↑ ↓ move, enter open, esc or ← back, q quit. Terminals that cannot read single keys get numbered menus. Vera never changes the graded output.

How it decides

ClearedDIFFERENT_ENTITYA fact proves it is someone else.

MatchedSAME_ENTITYThe facts show it is the customer. It goes to compliance.

ReviewREVIEWThe facts cannot settle it. An analyst decides.

One rule behind every choice

Wrongly clearing a sanctioned person is twenty times worse than an unneeded review. When the data is ambiguous, Vera picks the reading that cannot clear a hit. Anything that makes two people look more alike is safe to add; anything that makes them look different must be certain.

Clearing a hit that is really the customer60
Sending a different person to review3
Sending a real match to review2

A hit is cleared only by a contradiction

Time
The customer was 7 when the fraud report was written.
Date of birth
Customer born in 1988, hit born in 1952.
Location
Every country tied to the customer differs from every country tied to the hit.
Verified name
The passport name matches none of the hit's names.
Type
One is a person, the other a company.
Death
The listed person died before the customer was screened.

A hit is confirmed only when name and date of birth agree (name and country for a company) and nothing contradicts them. Missing information is never a mismatch: a birth year alone can still agree with a full date.

What happens to a hit

  1. s1_load.pyRead the tables and check every alert's hit list.
  2. s2_customers.pyWork out who the customer is: links, merged records, approved identity checks, notes.
  3. s3_hit_facts.pyRead what the listing says: birth dates, countries, dated reports, death.
  4. s4_decide.pyApply the policy rules. Output a decision, reason code, reason and evidence.
  5. s5_batch.pyCheck every row, then write the output file in order.

Every fact carries the ID of the record it came from, so a decision can cite exactly what decided it. The pipeline is standard-library Python with fixed rules, so the same input gives the same output on every run. A row that fails its checks stops the run with an error instead of writing a partial file.

Install, update, remove

Check what you have

git --version
python3 --version    # Windows: python --version

You need Git and Python 3.10 or later.

Run on your own data

vera path/to/data

To run the graded pipeline directly, from the repo folder:

system/run /path/to/screening/dev output/dev.jsonl
python -m unittest discover -s tests -t .

Update

Run the installer again, or pull the latest version yourself:

git -C ~/vera-cli pull
# Windows
git -C %USERPROFILE%\vera-cli pull

Remove

Delete the vera-cli folder. Then take Vera off your PATH: on macOS and Linux delete the # Vera lines in your shell startup file; on Windows remove the folder from the user Path variable in Environment Variables.

Data and safety

The development data comes from the event's participant data room and is for participants only; tests use invented names and dates. If a language model is used, it is called through OpenRouter with the key in OPENROUTER_API_KEY. Customer email drafts never mention screening, watchlists or sanctions, and nothing is ever sent.
